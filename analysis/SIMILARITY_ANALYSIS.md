# Embedding 向量相似度分析报告

## 概述

本报告分析了四个不同来源的 embedding 向量文件之间的相似度:
- `embedding_vllm_no_prompt.json` (vLLM)
- `embedding_ollama.json` (Ollama)
- `embedding_aws.json` (AWS)
- `embedding_sagemaker.json` (SageMaker)

所有向量均使用相同的模型: `BIaoo/lca-qwen3-embedding`

## 主要发现

### 1. 高度一致性组 (vLLM, Ollama, AWS)

这三个来源的向量表现出**极高的一致性**:

| 对比对 | 余弦相似度 | 欧氏距离 |
|-------|-----------|---------|
| vLLM vs Ollama | 0.999858 | 0.0169 |
| vLLM vs AWS | 0.999628 | 0.0273 |
| Ollama vs AWS | 0.999776 | 0.0211 |

**结论**: 三者相似度均超过 **99.96%**,说明这三个平台对同一模型的实现非常一致。

### 2. 异常情况 (SageMaker)

SageMaker 的向量与其他三个来源存在**显著差异**:

| 对比对 | 余弦相似度 | 欧氏距离 (原始) | 欧氏距离 (归一化后) |
|-------|-----------|----------------|-------------------|
| vLLM vs SageMaker | 0.249288 | 113.82 | 1.225 |
| Ollama vs SageMaker | 0.248630 | 113.82 | 1.226 |
| AWS vs SageMaker | 0.248047 | 113.82 | 1.226 |

**关键发现**:
- 余弦相似度仅约 **25%**
- SageMaker 的向量**未归一化** (范数 = 114.07)
- 即使归一化后,相似度仍然很低

## 分析与结论

### vLLM, Ollama, AWS 的一致性

这三个平台生成的向量几乎完全相同,说明:
1. 它们使用了相同的模型权重
2. 推理过程实现一致
3. 输出格式标准化(L2归一化)

### SageMaker 的差异原因

SageMaker 向量与其他三者差异巨大,可能原因:

1. **未归一化**: 向量范数为 114,而不是标准的 1.0
2. **不同的后处理**: 即使归一化后相似度仍只有 25%
3. **可能的原因**:
   - 使用了不同版本的模型
   - 不同的推理配置或参数
   - 数据预处理差异
   - 模型部署方式不同

### 建议

1. **使用 vLLM, Ollama 或 AWS**: 如果需要一致性,这三个平台均可使用
2. **检查 SageMaker 配置**: 需要进一步调查为什么 SageMaker 的输出如此不同
3. **标准化流程**: 建议对所有平台的输出进行归一化处理
